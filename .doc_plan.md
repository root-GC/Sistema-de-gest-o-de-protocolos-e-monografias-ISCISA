# Plano de Implementação — Documentos do Comité Científico (CC)

## 1. Documentos Exigidos para o CC

| # | Documento | Descrição | Auto-gerado |
|---|-----------|-----------|-------------|
| 1 | Carta de Cobertura | Documento de apresentação do protocolo | Não |
| 2 | Credenciais | Credenciais académicas do estudante/pesquisador | Não |
| 3 | Declaração de Originalidade | Declaração de que o trabalho é original | Não |
| 4 | Declaração do Registo Académico | Comprovativo de matrícula | Não |
| 5 | Declaração do Extracto Financeiro | Comprovativo de situação financeira regular | Não |
| 6 | Lista de Autores e Responsabilidade | Autores e respectivas responsabilidades | Não |
| 7 | Parecer do Núcleo | Parecer emitido pelo Núcleo Científico | **Sim** (pelo sistema) |

> O **Parecer do Núcleo** (#7) é gerado automaticamente pelo `DocumentGenerationService::generateOpinionPdf()` quando o NC conclui a deliberação. O sistema cria o registo com `enviado=true, aprovado=null` — a secretaria apenas confirma.

## 7. Novos Métodos no `ProtocolService.php`

### 7.1 `initializeCCDocuments(Protocol $protocol, string $parecerPath, string $parecerFileName)`

Cria os 7 registos de documentos quando o NC aprova.

**Quando:** chamado dentro de `EvaluationService::processDecision()` após aprovação do NC.

**Lógica:**
- Array com os 7 nomes de documentos
- Para o "Parecer do Núcleo": `enviado=true, file_path/preenchido`
- Para os restantes: `enviado=false`

### 7.2 `getCCDocuments(Protocol $protocol): Collection`

Retorna todos os `ProtocolDocumentRequirement` do CC para o protocolo.

### 7.3 `submitCCDocument(Protocol $protocol, User $student, string $nome, UploadedFile $file): ProtocolDocumentRequirement`

- Valida: estudante é dono do protocolo
- Valida: status === `protocol_documents_pending_cc`
- Guarda ficheiro em `storage/app/public/protocols/{id}/cc/`
- Atualiza registo: `enviado=true, aprovado=null, rejection_reason=null, reviewed_by=null, reviewed_at=null`

### 7.4 `approveCCDocument(Protocol $protocol, User $secretary, int $requirementId): ProtocolDocumentRequirement`

- Valida: secretaria é do CC
- Valida: registo pertence ao protocolo e é do CC
- `aprovado=true, reviewed_by, reviewed_at`
- Após aprovação, verificar `areDocumentsComplete()`:
  - Se true → avançar status para `protocol_pending_comite_cientifico` + atualizar `current_organ_id`

### 7.5 `rejectCCDocument(Protocol $protocol, User $secretary, int $requirementId, string $reason): ProtocolDocumentRequirement`

- Valida: secretaria é do CC
- Valida: registo pertence ao protocolo e é do CC
- `aprovado=false, rejection_reason, reviewed_by, reviewed_at`
- Notifica estudante

### 7.6 `areDocumentsComplete(Protocol $protocol, string $organType): bool`

```php
public function areDocumentsComplete(Protocol $protocol, string $organType): bool
{
    $total = ProtocolDocumentRequirement::where('protocol_id', $protocol->id)
        ->where('required_for_organ', $organType)->count();

    if ($total === 0) return false;

    $approved = ProtocolDocumentRequirement::where('protocol_id', $protocol->id)
        ->where('required_for_organ', $organType)
        ->where('enviado', true)
        ->where('aprovado', true)
        ->count();

    return $total === $approved;
}
```

## 13. Considerações Finais

1. **Parecer do Núcleo** é gerado pelo sistema e já fica como `enviado=true`. A secretaria apenas confirma (aprova ou rejeita).

2. **Notificações**: Quando um documento é rejeitado, o estudante deve ser notificado com o motivo. A implementação das notificações pode ser feita posteriormente (apenas a lógica de rejeitar + motivo fica pronta).

3. **Resubmissão**: O estudante pode resubmeter apenas o documento rejeitado. Não precisa reenviar todos.

4. **Transição automática**: Quando `areDocumentsComplete()` retorna `true`, o sistema avança automaticamente para `protocol_pending_comite_cientifico`. Isso pode acontecer:
   - Imediatamente após aprovação do último documento pendente
   - Ou pode ser feito sob demanda (quando a secretaria tenta atribuir revisores)

5. **`current_organ_id`**: Mantém-se no NC enquanto `status = protocol_documents_pending_cc`. Só muda para o CC quando avança para `protocol_pending_comite_cientifico`.

6. **Extensibilidade**: O mesmo padrão será replicado para a Bioética (com os documentos específicos dela e o status `protocol_documents_pending_bioetica`).
